# AI PM 블로그

시안 2 디자인으로 만든 정적 블로그입니다. 따로 설치할 것 없이 Node.js만 있으면 됩니다.

> AI 코딩 도구(에이전트)가 지켜야 할 규칙, 명령, 폴더 구조는 [CLAUDE.md](CLAUDE.md)에 있습니다. `AGENTS.md`는 같은 파일을 가리키는 바로가기입니다.

## 글 쓰기

`posts/` 폴더에 `.md` 파일을 하나 만들면 글 한 편이 됩니다. 파일 맨 위에 아래 다섯 줄을 적어 주세요.

```
---
title: 글 제목
date: 2026-11-20
category: portfolio
summary: 목록에 보일 한두 문장 요약
---
```

`category`는 `portfolio`, `retrospective`, `study` 중 하나입니다. 공개 글(`portfolio`, `study`)은 `posts/` 폴더에 둡니다. 본문은 마크다운(제목 `##`, 목록 `-`, 굵게 `**`, 링크, 이미지, 코드, 인용)을 쓸 수 있습니다.

## 회고는 나만 보는 글

회고(`retrospective`)는 `private/` 폴더에 쓰세요. 이 폴더는 깃헙에 올라가지 않고, 기본 빌드에도 들어가지 않습니다. `posts/`에 회고 글을 두면 빌드가 오류로 알려 줍니다. 내 컴퓨터에서 회고까지 포함해 보려면 아래처럼 빌드하세요. 이 결과(`dist/`)는 인터넷에 올리지 마세요.

```
node build.js --with-private
```

## 만들고 확인하기

```
node build.js --ssr
```

배포용 빌드예요. `dist/`에는 이미지·스타일·스크립트만 만들어지고, 서버에서 쓸 꾸러미는 `functions/site/`에 만들어져요. 페이지(HTML)는 사이트가 열릴 때마다 서버 함수(`site`)가 최신 글로 그리기 때문에, `dist/`의 `index.html`로는 볼 수 없어요.

내 컴퓨터에서 페이지를 파일로 미리 보고 싶을 때만 옵션 없이 `node build.js`를 써요. `dist/index.html`이 만들어지지만 이 결과는 **배포하지 마세요**(정적 파일이 서버가 그린 최신 페이지를 가려서 글이 바로 반영되지 않아요). 미리 본 뒤에는 `node build.js --ssr`로 `dist/`를 다시 만들어 두세요.

## 이름과 문구 바꾸기

`site.config.json`에서 블로그 이름, 메인 문구, 소개 한 줄, 메뉴를 바꿉니다. 소개 페이지는 `about.md`입니다. 이미지는 `assets/` 폴더에 넣고 글에서 `![설명](../assets/파일.jpg)`로 넣어 주세요.

## 인터넷에 올리기

`node build.js --ssr`로 빌드한 뒤 파이어베이스에 배포해요. 배포 명령과 확인할 것은 [CLAUDE.md의 자주 쓰는 명령](CLAUDE.md#자주-쓰는-명령)에 있어요. `dist/`만 Vercel, Netlify 같은 곳에 올리면 안 돼요. 페이지는 서버 함수가 그리기 때문이에요.

## 검색 노출(SEO) 설정

`site.config.json`에서 아래 값을 채워 주세요. 값이 없으면 해당 기능은 건너뛰고, 빌드가 끝날 때 알림으로 알려 줘요.

| 설정 | 하는 일 |
|---|---|
| `siteUrl` | 사이트 주소(예: `https://내주소.com`). 대표 주소(canonical), 사이트맵, RSS, 공유 이미지 주소를 만드는 데 꼭 필요해요. 빌드할 때 `node build.js --site-url=https://내주소.com`로 넣어도 돼요. |
| `description` | 첫 화면과 공유 카드에 쓰는 사이트 설명(80~150자 정도) |
| `cleanUrls` | `true`로 하면 주소에서 `.html`을 뗀 형태(`/posts/글이름`)를 대표 주소로 써요. 호스팅도 같은 방식으로 설정해야 해요. |
| `ogImage` | 글에 이미지가 없을 때 공유 카드에 쓰는 기본 이미지(1200x630 PNG/JPG) |
| `googleVerification`, `naverVerification` | 구글 서치콘솔, 네이버 서치어드바이저에서 받은 확인 코드 |

글 머리말에 `description`(검색 결과 설명)과 `image`(공유 이미지 경로, PNG/JPG)를 적으면 그 글에만 따로 적용돼요. 없으면 `summary`와 기본 이미지를 써요.

빌드하면 자동으로 만들어지는 것: 글마다 설명(description)·공유 카드·구조화 데이터(BlogPosting, 글 경로), `sitemap.xml`, `robots.txt`, `rss.xml`, `404.html`, 아이콘. 관리자 화면과 404는 검색에서 빠지도록(noindex) 표시돼요. 비공개 메뉴(회고)는 어디에도 들어가지 않아요.

## 배포 후 할 일

1. 구글 서치콘솔과 네이버 서치어드바이저에 사이트를 등록하고 `sitemap.xml`을 제출해요.
2. 공유 카드가 잘 보이는지 카카오톡·X·LinkedIn에 주소를 붙여 확인해요.
3. 구글 PageSpeed Insights로 속도를 확인해요.
4. 공개 전에 `[샘플]` 글, `[이름]`, `[이메일 주소]`를 모두 바꾸거나 지워요.

## 관리자 로그인과 글 저장 (파이어베이스)

- **주소:** 사이트의 `admin/login.html`에서 로그인해요. 로그인한 관리자만 `admin/write.html`(글쓰기·수정)과 `admin/posts.html`(글 관리)을 쓸 수 있어요.
- **저장 위치:** 글은 파이어베이스 프로젝트 `my-blog-test-b439a`의 데이터베이스(Firestore) `posts`에 저장돼요. 본문은 서식이 있는 HTML로 저장해요(`format` 값이 `html`). 저장하고 보여 줄 때 허용한 태그만 남기고 걸러서 글에 심은 코드가 실행되지 않아요. 예전에 마크다운으로 저장한 글(`format`이 `md`)도 그대로 읽혀요.
- **관리자 계정 정하기(처음 한 번):** 관리자는 Google 계정이에요. 이메일·비밀번호로는 로그인하지 않아요.
  1. 관리자로 쓸 Google 계정으로 `admin/login.html`에서 "Google 계정으로 로그인"을 한 번 눌러요. 아직 관리자 표시가 없으면 "이 구글 계정에는 관리자 권한이 없어요"라고 나오고 들어가지는 못하지만, 이때 파이어베이스 Authentication에 그 계정이 만들어져요.
  2. 그 Google 계정의 이메일을 Claude에게 알려 주면 관리자 표시(admin)를 붙여요. 표시를 붙인 뒤에는 한 번 로그아웃했다가 다시 로그인해야 적용돼요.
- **평가자 임시 입장:** 로그인 화면의 "평가자 입장"에 운영자가 알려 준 접속 코드를 넣으면 만료 전까지 관리자 화면을 둘러보고 글을 쓸 수 있어요(회고 포함). **글·메뉴·조회수·댓글을 지우는 것은 막혀 있어요.** 코드의 해시와 만료일은 데이터베이스 `reviewerAccess/current`에 있고(화면에서는 아무도 못 읽어요), 서버 함수 `reviewer`(`/api/reviewer`)가 맞는지 확인해 그 익명 계정에 평가자 표시와 만료 시각(`until`, 최대 12시간)을 붙여요. 코드를 10번 틀리면 15분 동안 멈춰요. 새 코드를 만들거나 막으려면 Claude에게 말해 주세요(`reviewerAccess/current`를 바꾸면 새 입장이 바로 막혀요).
- **이메일·비밀번호 로그인은 꺼 두었어요**(`firebase.json`의 `emailPassword: false`). 회원가입 화면도 없어요. 관리자 권한은 정해 둔 Google 계정 **한 개**만 갖고, 일반 방문자는 Google 로그인으로 댓글 권한만 가져요.
- **글은 바로 반영돼요.** 사이트의 페이지는 방문할 때마다 서버(Cloud Functions `site`)가 파이어베이스의 최신 공개 글로 그려요. 글을 쓰고, 고치고, 지우거나 메뉴 이름·순서를 바꾸면 따로 배포하지 않아도 새로고침하면 바로 보여요. 댓글과 조회수도 바로 반영돼요. (나만 보기 글과 회고는 사이트에 들어가지 않아요.)
- **카테고리를 바꾸려면:** `site.config.json`의 `categories`뿐 아니라 `firestore.rules`의 카테고리 목록도 같이 고치고 배포해야 해요.
- **비공개 메뉴 이름(회고):** 공개되는 파일에 넣지 않으려고 데이터베이스의 `settings/private` 문서에 두었어요. 관리자가 로그인하면 불러와서 글쓰기 메뉴에 보여 줘요.

## 배포하기 (파이어베이스 호스팅 + 서버 함수)

- **주소:** https://my-blog-test-b439a.web.app (프로젝트 `my-blog-test-b439a`)
- **글·메뉴·댓글을 바꿀 때는 배포가 필요 없어요.** 서버가 매번 최신으로 그려요.
- **코드(디자인, 스크립트, 서버 함수)를 바꿨을 때만 배포해요.** 순서: (1) `node build.js --ssr`(이미지·스타일·스크립트를 `dist/`에, 서버 꾸러미를 `functions/site/`에 만들어요) (2) Claude에게 "배포해줘"라고 하거나 `firebase deploy --only functions,hosting`을 실행해요.
- `node build.js`(옵션 없음)는 모든 페이지를 `dist/`에 파일로 만들어요. 내 컴퓨터에서 미리 볼 때만 쓰고, **이 결과를 그대로 배포하지는 마세요.** 정적 파일이 있으면 서버가 그린 페이지보다 먼저 보여서 글이 바로 반영되지 않아요. (`--no-remote`도 마찬가지예요.)
- 서버가 `/robots.txt`를 가로채서 404를 돌려주기 때문에, `robots.txt`만은 `--ssr` 빌드가 정적 파일로 만들어요.
- 스크립트·스타일·설정 파일과 페이지는 모두 캐시를 쓰지 않아서, 배포 직후부터 새 내용이 보여요.
- 구글 로그인은 `my-blog-test-b439a.web.app`과 `localhost`에서 쓸 수 있어요. 새 도메인을 연결하면 파이어베이스 콘솔(Authentication → 설정 → 승인된 도메인)에 추가해야 해요.
