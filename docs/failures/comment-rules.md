# 일반 구글 계정으로 댓글이 안 달림

## 막힌 일

관리자가 아닌 일반 구글 계정으로 로그인한 방문자가, 공개 글에서 댓글을 쓰고 [댓글 등록]을 누르면 아래 안내가 뜨고 저장되지 않았어요(2026-11-25 운영자가 발견).

> 권한이 없어요. 다시 로그인한 뒤 시도해 주세요.

로그인 상태(이름 표시, 로그아웃 링크)와 글(공개)은 모두 정상이었어요.

## 원인

보안 규칙(`firestore.rules`)의 `isAdmin()`이 관리자 표시(custom claim)를 `request.auth.token.admin == true`로 바로 읽었어요. **관리자 표시가 없는 계정(일반 방문자)에서는 이 값이 `false`가 아니라 오류**가 돼요. 댓글 쓰기 조건에 `d.admin == isAdmin()`이 들어 있어서, 일반 방문자는 이 오류 때문에 규칙 전체가 거부(`permission-denied`)됐어요.

- 관리자 계정은 표시가 있어서 통과했기 때문에 지금까지 드러나지 않았어요.
- 2026-11-17에 댓글 규칙을 만들 때 "실제 로그인 상태에서의 허용 동작은 가짜 파이어베이스로만 시험했다"(`decisions.md`)고 적어 둔 부분이 실제로 비어 있던 곳이에요. 가짜 파이어베이스는 이 규칙을 실행하지 않아서 잡지 못했어요.
- 같은 파일의 `isStaff()`는 2026-11-25에 이미 `token.get('admin', false)`를 쓰고 있었어요.

## 푼 방법

`isAdmin()`을 `request.auth.token.get('admin', false) == true`로 바꿔 배포했어요(`deploy --only firestore:rules`). 관리자 표시가 없는 계정은 오류 대신 `false`가 돼요. 권한은 넓어지지 않아요(관리자만 관리자로 인정, 삭제·수정 규칙은 그대로).

배포 뒤 **로그인 없이** 시험한 결과: 댓글 쓰기·글 만들기·글 삭제 403, 나만 보기 메뉴 설정·AI 기록 읽기 403, 공개 글·댓글 읽기 200.

운영자가 같은 구글 계정으로 같은 글에서 다시 등록해 **댓글이 달리는 것을 확인**했어요(2026-11-25).

## 다음에 조심할 것

규칙에서 로그인 정보의 값(`request.auth.token.xxx`)을 읽을 때는 표시가 없는 계정도 생각해서 항상 `token.get('xxx', 기본값)`을 쓰고, 일반 방문자 계정으로 허용되는 동작(댓글 쓰기)은 가짜가 아니라 실제 규칙으로 한 번 시험해요.
