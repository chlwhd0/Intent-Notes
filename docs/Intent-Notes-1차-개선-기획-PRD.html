2. 개요

배경: 1차 개선으로 블로그는 관리자 글쓰기, 방문자 구글 로그인과 댓글, 조회수, 공유하기, 이미지·파일 첨부, GA4 연결까지 갖췄습니다. 그런데 "어떤 글이 인기 있는가"를 판단하려고 GA4를 열어 보면, 글이 열렸는지는 보이지만 읽혔는지(완독), 반응을 이끌었는지(댓글·공유·좋아요·스크랩)는 보이지 않습니다.

문제: 사이트의 핵심 행동(읽기, 댓글, 공유, 검색)이 페이지 안에서 일어나 주소가 바뀌지 않기 때문에 GA4의 자동 측정에 잡히지 않습니다. 글 주소가 글 번호라서 메뉴별 비교도 어렵고, 좋아요·스크랩은 기능 자체가 없으며, 운영자의 방문이 통계에 섞이는 경로도 남아 있습니다.

솔루션: (1) GA4로 보내는 이벤트와 파라미터를 설계해 완독·댓글·공유·글 선택 위치·검색·로그인·첨부 다운로드를 측정하고, (2) 좋아요와 스크랩 기능을 만들어 "반응" 지표를 확보하며, (3) GA 콘솔 설정과 월간 분석 대시보드를 갖춰 인기 글을 몰입·반응·확산 세 축으로 판단할 수 있게 합니다.

3. 문제

3.1 데스크리서치

1인 운영 블로그이므로 시장조사 대신 "현재 분석 체계의 진단(SWOT)"과 "분석 도구 관점의 3C"로 정리했습니다. 경쟁 서비스 항목은 일반적으로 알려진 수준이며, 서비스별 세부 기능은 후속 확인이 필요합니다.

3.1.1 SWOT 분석 (블로그 분석 체계 기준)

강점 (Strength)약점 (Weakness)
  • 페이지마다 고유 주소가 있고 서버가 완성된 HTML을 그려서 GA4의 page_view가 정확하다
  • GA4 연결과 실시간 수신이 확인되었다
  • 조회수, 댓글 같은 자체 데이터를 데이터베이스(Firestore)에 가지고 있다
  • 관리자 브라우저 제외 로직과 이벤트 설계 문서(택소노미 v1.0)가 있다
  • 완독, 댓글, 공유(링크 복사), 글 선택 위치, 검색어, 로그인이 GA4에 없다
  • 좋아요, 스크랩 기능이 없어 측정할 대상 자체가 없다
  • 글 주소가 글 번호라 GA에서는 페이지 제목으로만 구분되고, 메뉴별 비교가 안 된다
  • 직접 센 조회수와 GA 숫자가 서로 다른 장부다
  • GA 콘솔 설정(맞춤 정의, 핵심 이벤트, 데이터 보관)이 아직 되어 있지 않다
  • 분석·개발 리소스가 1인 운영이라 제한적이다
기회 (Opportunity)위협 (Threat)
  • 이벤트 몇 개만 추가해도 인기 글을 몰입·반응 기준으로 판단할 수 있다
  • Looker Studio(GA4 연결)로 무료 월간 대시보드를 만들 수 있다
  • 좋아요·스크랩은 재방문과 충성도의 신호가 된다
  • 구글·네이버 검색 등록 후 유입이 늘면 분석 가치가 커진다
  • 광고 차단, 측정 거부 방문자는 GA에 잡히지 않는다
  • 스크랩 목록 등 저장하는 개인정보가 늘어난다(처리방침 갱신 필요)
  • 맞춤 측정기준은 등록 이후에만 쌓이고 소급되지 않는다 (등록이 늦을수록 데이터 손실)
  • 방문자가 적을 때 순위를 믿고 판단하면 잘못된 결론이 난다

3.1.2 3C 분석

구분내용시사점
고객 (Customer)
  • 운영자: 다음에 쓸 글을 데이터로 정하고 싶다
  • 방문자(채용 담당자, 동료 PM): 글의 반응(좋아요, 댓글)으로 글의 가치를 가늠하고, 마음에 드는 글을 저장해 두고 싶다
 운영자용 분석(GA)과 방문자용 반응 표시(좋아요·스크랩 수)를 따로 설계한다
경쟁 (Competitor)
  • 플랫폼 블로그(네이버 블로그, 티스토리 등)는 조회, 유입 경로, 공감(좋아요), 댓글 같은 통계를 운영 화면에서 기본 제공하는 것으로 알려져 있다
  • 범용 분석 도구(GA4)는 자유도가 높지만, 무엇을 볼지 직접 설계해야 보인다
 직접 만든 블로그의 약점은 "기본 통계가 없다"는 점이므로, 측정 설계가 곧 제품 기능이다
자사 (Company)직접 개발한 블로그. 화면·데이터·측정을 모두 마음대로 바꿀 수 있고 배포 없이 글이 반영된다. 반면 모든 측정을 직접 심어야 한다측정 설계를 한 번 정리해 두면 이후 글이 늘어도 그대로 쓸 수 있다

PRB-10내 방문이 통계에 섞인다관리자 로그인 표시가 있는 브라우저만 측정에서 빠지고, 로그아웃하면 그 표시도 지워져 이후 내 방문이 측정된다소유자 브라우저 표시를 로그아웃 후에도 유지 + GA 내부 트래픽 필터
PRB-11로그인·로그아웃 때 page_view가 한 번 더 잡힌다로그인·로그아웃 직후 같은 페이지를 새로고침하기 때문이다새로고침 없이 화면만 갱신
PRB-12GA 콘솔 설정이 비어 있다맞춤 측정기준 미등록, 핵심 이벤트 미지정, 데이터 보관 기본값(짧음), 내부 트래픽 필터 없음, 향상된 측정 확인 안 함GA 콘솔 설정 체크리스트 수행
PRB-13분석을 보는 화면이 없다GA 화면을 매번 직접 조합해야 하고, 자체 데이터(댓글 수 등)는 관리자 화면에서 볼 수 없다월간 인기 글 대시보드(Looker Studio) + 관리자 글 목록에 반응 열 추가
PRB-15글 길이가 달라 읽기율·체류 시간을 공정하게 비교할 수 없다짧은 글은 금방 읽히고 긴 글은 오래 걸린다. 글 길이를 모르면 "체류 시간이 짧은 글 = 인기 없는 글"로 잘못 판단한다. 글 글자 수가 GA에 전달되지 않는다글 글자 수를 이벤트에 함께 보내고, 글 길이 구간별 읽기율과 "길이 대비 참여 시간"을 지표로 정의
PRB-14측정하는 정보가 처리방침에 반영되어야 한다좋아요·스크랩은 계정 식별 번호와 글 번호를 저장하므로 개인정보 처리방침 갱신이 필요하다처리방침 문구 갱신

3.3 문제 검증

1인 운영 블로그라 설문 대신 "운영자가 알고 싶은 지표"를 GA4에서 실제로 볼 수 있는지 점검하는 방식으로 검증했습니다 (코드 확인, GA 이벤트 체계 점검, 실시간 수신 확인).

3.3.1 설문 조사 계획

항목내용
실시 여부실시하지 않음. 현재 사용자가 운영자 본인뿐이고 방문자가 적어 설문 표본을 확보하기 어렵다
대체 검증(1) 운영자가 요청한 지표 목록 대 GA4 현황 점검 (2) 방문자 데이터가 쌓인 뒤 4주 시점에 재검증
후속 계획공개 후 방문자가 늘면 "반응 기능(좋아요·스크랩)을 쓰는가"를 사용 데이터로 확인하고, 필요하면 방문자 설문을 추가한다

3.3.2 점검 결과 및 인사이트

#운영자가 알고 싶은 지표GA4 현재근거
1홈 화면 방문자 수가능page_view와 사용자 수가 자동으로 쌓인다 (홈 두 주소 문제는 고침, 이전 데이터만 두 줄)
2페이지별 방문자 수가능페이지 및 화면 보고서

5완독 여부부분scroll 90% 한계 (PRB-01)
6댓글을 이끌어 냈는가불가GA로 전송하지 않음 (PRB-02)

8좋아요를 이끌어 냈는가불가기능 없음 (PRB-04)
9스크랩을 이끌어 냈는가불가기능 없음 (PRB-04)

인사이트: 필수 지표 9개 중 GA4에서 확인 가능한 것은 4개(44%), 부분 가능이 2개, 불가가 3개입니다. 확인 가능한 4개는 모두 "열렸나"에 관한 것이고, 인기 글 판단에 필요한 "읽혔나(몰입)"와 "반응했나"는 비어 있습니다.

3.4.2 문제 최종 정의

구분내용
핵심 문제인기 글을 판단하는 데 필요한 "몰입(읽혔나)"과 "반응(좋아요·댓글·공유·스크랩)"이 GA4에서 측정되지 않아, 지금은 "열린 횟수"로밖에 인기를 말할 수 없다.
선정 이유필수 지표 9개 중 5개가 비어 있고, 그중 대부분이 한 번의 이벤트 설계로 해결된다. 소급이 안 되므로 늦을수록 데이터를 잃는다

6.5 유즈케이스 시나리오

시나리오동작 흐름남는 데이터
S1. 방문자가 글을 읽고 반응
  1. 첫 화면 타일을 눌러 글 진입 (select_content 위치=home_tile)
  2. 본문을 읽으며 진행도 이벤트, 끝까지 읽으면 post_read
  3. 공유하기에서 "링크 복사" (share method=copy_link)
  4. 구글 로그인 후 댓글 등록 (login, comment_submit)
선택 위치, 완독, 공유 방법, 로그인, 댓글이 모두 같은 post_id로 연결
S2. 방문자가 좋아요·스크랩
  1. 로그인하지 않은 상태에서 좋아요를 누르면 로그인 안내가 나온다
  2. 구글 로그인 후(새로고침 없이) 좋아요 + 스크랩
  3. 사이드바 "내 스크랩"에서 저장한 글을 다시 연다
post_like, post_bookmark (add), 재방문
S3. 운영자가 월간 분석
  1. 대시보드에서 기간(지난 30일)과 메뉴를 고른다
  2. 몰입 순위(읽은 글 수, 읽기율), 반응 순위(반응률), 확산(유입 소스)을 본다
  3. 관리자 글 목록에서 댓글·좋아요·스크랩 수를 확인한다
  4. 다음 글의 주제와 길이를 정한다
월간 리포트 메모 (의사결정 문서에 기록)
S4. 운영자가 글을 확인관리자로 로그아웃한 뒤 공개 글을 열어도 측정되지 않는다내 방문 혼입 없음
