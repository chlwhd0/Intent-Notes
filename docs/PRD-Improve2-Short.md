## 2. 개요

**글 한 편이 만들어져 공개되고 읽히기까지의 반복 작업과 실수 위험을, "AI는 제안만 하고 결정은 사람이 하는" 방식으로 덜어 주는 개선안입니다.**

- **현재**: 글쓰기, 로그인·댓글, 조회수, 공유, 첨부는 갖췄고 측정 체계는 1차 개선 PRD에서 설계했습니다. 그러나 요약·설명·제목은 손으로 쓰고, 공개 전 확인(실명, 내부 자료, 수치, 자리표시자)은 눈으로만 합니다.
- **문제**: 2026-11-24 공개 글 4개 중 **2개의 요약이 비어 있고(50%)**, 4개 모두 본문이 50자 이하이며, 푸터에 `[이름]`이 그대로 공개되어 있습니다.
- **이번 과제**: Phase A(안전과 틀) → B(글쓰기 보조·요약) → C(첨부 요약·회고 정리·추천). **범위 밖**: 방문자 질문 챗봇, 번역, 댓글 AI, AI의 자동 발행·수정.

### 3.2 문제 검증

설문 대신 **공개 사이트에서 지금 확인되는 사실**로 검증했습니다(2026-11-24 공개 글 4개와 푸터). 관리자 로그인이 필요한 화면은 직접 보지 못했습니다.

| 확인한 것 | 확인 결과 | 연결 문제 |
|---|---|---|
| 공개 글의 한 줄 요약 | **4개 중 2개가 비어 있음 (50%)** | `APRB-01` |
| 본문 길이, 첨부 | 4개 모두 50자 이하, 2개는 내용이 PDF에만 있음 | `APRB-05` `07` |
| 자리표시자 | **푸터에 `[이름]`이 그대로 보임**, 빌드 점검은 설정·제목만 경고 | `APRB-03` `04` |

방문자 쪽(`07`, `08`)과 AI 신뢰·비용(`09`, `10`)은 증거가 약하거나 새 기능이라 만든 뒤 지표로 확인하는 가설로 둡니다.

### 3.3 문제 최종 정의

- **우선순위(RICE·MoSCoW, 추정치)**: Must = AI 표시·승인·한도(13.5), 규칙 점검·발행 막기(12.0) / Should = 글쓰기 보조(6.4), AI 문맥 점검(3.0), 3줄 요약(1.7) / Could = 첨부 요약(1.1), 회고 정리(0.7), 추천(0.5) / Won't = 챗봇·번역·댓글 AI(0.3).

| 최종 문제 | 한 문장 정의 | 묶인 문제 |
|---|---|---|
| `AFP1` **작성 부담** | 요약·설명·제목을 매번 손으로 쓰고, 내용이 PDF·회고에 있어 옮기기 번거롭다 | `APRB-01` `02` `05` `06` |
| `AFP2` **공개 전 안전** | 실명·내부 자료·수치·자리표시자를 눈으로만 확인한다 | `APRB-03` `04` |
| `AFP3` **독자 이해** | 방문자가 글의 핵심을 빨리 알고 이어 볼 글을 찾기 어렵다 | `APRB-07` `08` |
| `AFP4` **AI 신뢰·통제** | AI 결과가 틀려도 걸러지지 않고, 비용과 원문 전송이 통제되지 않을 수 있다 | `APRB-09` `10` |

> **최종 정의:** 글을 쓰고 공개하는 반복 작업과 공개 전 실수 위험을 사람이 혼자 감당하고 있어, **"AI는 제안만 하고 사람이 확인하는" 방식**으로 덜어 주되 신뢰·비용·개인정보를 통제해야 한다. `AFP4`는 모든 AI 기능의 전제라 가장 먼저 만든다.

## 4. 가설 및 지표

### 4.1 핵심 지표

가설 ID에는 부모 최종 문제가 들어 있습니다. 글이 4개뿐이라 **운영자 쪽 지표를 먼저 판단 기준**으로 삼고, 방문자 지표(1차 개선 PRD의 `post_read`, `select_content`)는 조회 50 이상 글에만 씁니다.

| 가설 | 지표 | 현재 | 목표 |
|---|---|---|---|
| `AFP1-H1` 글쓰기 보조가 요약·설명을 채운다 | 요약 채움률, 제안 적용률 | 50%, 측정 전 | 100%, 적용률은 4주 뒤 기준값 확정 |
| `AFP1-H2` 제목 후보는 참고용으로 쓰인다 | 그대로 적용 vs 고쳐서 발행 비율 | 측정 전 | 측정 시작 |
| `AFP1-H3` PDF 요약이 읽기를 늘린다 | 요약 넣은 글 vs 안 넣은 글의 읽기율 | 측정 전 | 측정 시작 |
| `AFP1-H4` 회고 정리가 공개 글을 늘린다 | 회고 기반 공개 글 수, 초안→발행 전환율 | 측정 전 | 측정 시작 |
| `AFP2-H1` 규칙 점검·발행 막기로 위반이 남지 않는다 | 공개 글 위반 건수(월 1회 전수 점검) | 1건 이상 | 0건 |
| `AFP2-H2` AI가 문맥 위험을 보완한다 | AI가 찾은 건 중 "맞다"고 한 비율(표본 20건) | 측정 전 | 합격선은 12절에서 결정 |
| `AFP3-H1` 3줄 요약이 읽기를 돕는다 | 요약 있는 글 vs 없는 글의 읽기율, 펼침 비율 | 측정 전 | 읽기율 같거나 높음 |
| `AFP3-H2` 추천이 추가 열람을 만든다 | 추천 선택률(`location=related`) | 없음 | 측정 시작 |
| `AFP4-H1` 표시와 [적용] 승인이면 틀린 내용이 안 나간다 | 공개 후 고친 AI 문장 수 | - | 0건 |
| `AFP4-H2` 저장 때 1회 생성과 월 한도가 비용을 통제한다 | 방문자 열람당 AI 호출, 월 비용 | - | 0회, 월 한도 이내 |

### 4.2 고객 정의 · 화면 문구

**1순위 운영자**(글을 쓰는 AI PM 준비자): 요약·설명·제목을 매번 써야 하고 공개 전에 실수가 남을까 마음을 졸입니다. **2순위 방문자**(채용 담당자·동료 PM): 짧은 시간에 핵심을 파악하고 이어서 읽습니다. 문구는 해요체를 유지하고, 관리자 화면은 **"AI 초안" + [적용]**, 방문자 화면은 **"AI 요약"·"AI 추천"**으로 AI가 만든 것을 분명히 표시합니다. 점검은 "해결 필요"(발행 막음)와 "확인 필요"("확인했어요")로 구분합니다.

## 5. 해결 방안

### 5.1 솔루션 정의

**목표: 운영자는 글쓰기와 공개 전 확인을 AI의 제안으로 덜고, 방문자는 글의 핵심과 이어 읽을 글을 바로 본다. 단, 공개되는 것은 내가 확인한 것뿐이다.** 해결방안 ID에는 부모 가설이 들어 있고(`AFP2-H1-S1` = `AFP2`의 `H1` 가설에서 나온 첫 해결방안, 점 뒤는 내용 키워드), 전체 목록은 6절 표입니다.

### 5.2 AS-IS / TO-BE

| 영역 | AS-IS | TO-BE |
|---|---|---|
| 요약·설명·제목 | 손으로 쓴다(요약 50% 비어 있음) | 본문에서 제안, [적용] |
| 공개 전 확인 | 지침 문장과 눈 | 저장 직전 점검(규칙 + AI), 해결 전 발행 막기 |
| 글 상세 | 제목, 조회수, 공유, 본문, 이전·다음 | 위쪽 "AI 요약", 아래 "이어서 읽을 글" |
| AI 호출·표시 | 없음 | 저장 때 1회만 호출, 모든 결과에 표시, 이용 기록 |

**컨셉** "AI는 제안, 결정은 사람". **타깃** 운영자 1순위, 방문자 2순위. **비즈니스 모델** 무료 유지(광고·유료 없음), AI 호출 비용이 새로 생기며 월 한도는 결정이 필요합니다.

### 5.3 예상 성과 (OKR)

**O**: 글을 쓰고 공개하는 반복 작업과 공개 전 실수 위험을 AI의 제안으로 줄인다. **KR1** 요약이 채워진 공개 글 50% → 100% · **KR2** 공개 화면의 자리표시자·전화번호 1건 이상 → 0건 · **KR3** 제안 적용률 4주 뒤 기준값 확정 · **KR4** 방문자 열람당 AI 호출 0회, 월 비용 한도 이내

## 7. 비기능적 요구사항

- **안정성**: AI가 틀릴 수 있다는 전제로 [적용] 전에 걸러지고, 방문자 요약은 관리자 확인 후에만 공개. AI 호출이 실패하거나 한도를 넘어도 글쓰기·발행·규칙 점검은 정상.
- **보안·개인정보**: AI 키는 서버 보안 설정에만 두고, 호출은 서버가 관리자 로그인을 확인한 뒤에만. 이용 기록은 관리자만 읽고 쓰며 규칙으로 강제. 방문자 이름·이메일·댓글은 AI로 보내지 않고 회고 원문은 "보내지 않기" 선택지를 둠.
- **성능·접근성**: 방문자 화면의 추가 스크립트 5KB 이하, 버튼·접기·체크박스는 키보드 사용 가능, "AI" 표시는 색에만 의존하지 않음, 모바일 폭에서 가로 스크롤 없음.

## 8. 디자인 요구사항

기존 시안 2(크림 사이드바, 세리프 제목, 테라코타 포인트)를 유지하고, AI가 만든 것은 **짙은 청록 "AI 초안" 표시**로 구분합니다. 글쓰기 화면은 왼쪽 입력과 오른쪽 "AI 도우미" 패널로 구성하고 모바일에서는 입력 아래로 내립니다. 프로토타입은 `prototypes/ai-features-mockups.html`입니다.

## 9. 출시 및 운영 전략

- **범위·방식**: Phase마다 나눠 배포합니다. **A** `AFR-12`~`15`, `06`, `07` / **B** `AFR-01` `02` `08` `09` `10`(AI 제공자·비용 결정 후) / **C** `AFR-03` `04` `05` `11`(A·B 이용 기록을 보고 진행 여부 결정). 보안 규칙을 바꾸는 A는 규칙 배포 → 로그인 없이·방문자 계정으로 거부 시험 → 화면 배포 순서입니다.
- **테스트**: 가짜 AI 응답(적용·무시·한도 초과·오류), 호출 거부, 서버의 발행 게이트, 위험 표현이 든 샘플 글 20건, 방문자 화면의 AI 호출 0회.

| 리스크 | 대응 |
|---|---|
| AI가 틀린 요약·점검을 낸다 | 표시 + [적용] 전에는 반영 안 함, 방문자 요약은 관리자 확인 후 공개 |
| 회고·PDF 원문이 외부 AI로 나가 정보가 샌다 | "원문 보내지 않기", 보내는 내용을 처리방침에 명시 |
| 호출 비용이 늘어난다 | 저장 때 1회만, 월 한도와 80% 알림 |
| 점검이 놓치거나 지나치게 막는다 | 규칙 점검이 기본, AI는 보완만, "확인했어요"로 사람이 최종 판단 |
