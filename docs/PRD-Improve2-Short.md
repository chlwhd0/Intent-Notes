# PRD 요약판 — Intent Notes 2차 개선 (AI 기능편)

> [PRD-Improve2.md](PRD-Improve2.md)(원본, v2.2)를 **2쪽 분량**으로 줄인 요약판입니다. 근거 표와 세부 기준은 원본을 보세요. 원본은 바꾸지 않았습니다.

**PRD 문서 이동:** [블로그 기획 PRD](PRD-Blog.md) · [1차 개선 PRD](PRD-Improve1.md) · [2차 개선 PRD 원본](PRD-Improve2.md) · **2차 개선 PRD 요약판**(이 문서)

## 1. 배경과 문제

글 한 편이 만들어져 공개되고 읽히기까지의 **반복 작업과 실수 위험**을 AI의 제안으로 줄입니다. 2026-11-24에 공개 사이트를 확인한 결과는 이렇습니다.

- 공개 글 4개 중 **2개의 한 줄 요약이 비어 있습니다(50%)**.
- 4개 모두 본문이 50자 이하이고, 그중 2개는 내용이 PDF 첨부에만 있습니다.
- 푸터에 자리표시자 **`[이름]`이 그대로 공개**되어 있습니다.
- 공개 전 확인(실명, 내부 자료, 수치, 자리표시자)은 지침 문장으로만 있고 사람이 눈으로 합니다. 회고(나만 보기)는 쌓여도 공개 글로 바뀌지 못합니다.

## 2. 문제 → 가설 → 지표

처음 발굴한 문제 10개(`APRB-01`~`APRB-10`)를 **최종 문제 4개**로 묶고 가설 10개를 세웠습니다. 글이 4개뿐이라 **운영자 쪽 지표를 먼저 판단 기준**으로 삼고, 방문자 지표는 조회 50 이상 글에만 씁니다.

| 최종 문제 | 묶인 문제 | 가설 | 확인 지표 |
|---|---|---|---|
| `AFP1` **작성 부담** | `APRB-01` `02` `05` `06` | `AFP1-H1` 글쓰기 보조 → 요약·설명이 채워지고 작성 시간이 준다<br>`AFP1-H2` 제목 후보는 참고용으로 쓰인다<br>`AFP1-H3` PDF 요약 → 읽기·내려받기가 늘어난다<br>`AFP1-H4` 회고 정리 → 공개 글이 늘어난다 | 요약 채움률(현재 50%), 제안 적용률, 작성~발행 시간, 읽기율(`post_read`), 회고 기반 공개 글 수 |
| `AFP2` **공개 전 안전** | `APRB-03` `04` | `AFP2-H1` 규칙 점검과 발행 막기 → 위반이 남지 않는다<br>`AFP2-H2` AI가 문맥 위험(실명 추정, 내부 자료)을 보완한다 | 공개 글 위반 건수(월 1회 전수 점검, 목표 0), AI 판정 정확도(표본 20건) |
| `AFP3` **독자 이해** | `APRB-07` `08` | `AFP3-H1` 3줄 요약 → 읽기율이 같거나 높고 펼쳐 보는 방문자가 있다<br>`AFP3-H2` 추천 글 → 추가 열람이 생긴다 | 읽기율, `summary_toggle`, `select_content`(`location=related`) |
| `AFP4` **AI 신뢰·통제** | `APRB-09` `10` | `AFP4-H1` "AI 초안" 표시와 [적용] 승인 → 틀린 내용이 공개되지 않는다<br>`AFP4-H2` 저장 때 1회 생성과 월 한도 → 비용이 통제된다 | 공개 후 고친 AI 문장 수(목표 0), 월 호출·비용, 방문자 열람당 AI 호출(목표 0) |

우선순위는 `AFP4`(RICE 13.5, Must)가 가장 높습니다. 모든 AI 기능의 전제 조건이라 **가장 먼저** 만들고, 다음이 `AFP2`(12.0, Must)입니다.

## 3. 해결방안과 기능 (15개)

해결방안 ID에는 부모 가설이 들어 있습니다(`AFP2-H1-S1` = `AFP2`의 `H1` 가설에서 나온 첫 해결방안, 점 뒤는 내용 키워드).

| 해결방안 ID | 해결 방안 | 기능 | 우선 |
|---|---|---|---|
| `AFP1-H1-S1.fill*meta` | 본문을 읽고 한 줄 요약·검색용 설명을 제안, 마음에 드는 것만 [적용] | `AFR-01` | P1 |
| `AFP1-H2-S1.title` | 제목 후보 3개 제안 | `AFR-02` | P1 |
| `AFP1-H3-S1.pdf*sum` | 첨부 PDF의 핵심 3줄을 본문에 넣기 | `AFR-03` | P2 |
| `AFP1-H4-S1.retro*draft` | 회고에서 반복되는 배움을 찾아 공개 글 초안 생성(처음엔 나만 보기) | `AFR-04` | P2 |
| `AFP1-H4-S2.retro*safe` | 회고 원문 보호(원문 그대로 쓰지 않기, 원문 외부 전송 안 하기 선택) | `AFR-05` | P2 |
| `AFP2-H1-S1.rule*check` | 자리표시자·전화번호·정확한 수치를 규칙으로 점검(AI 없이) | `AFR-06` | P0 |
| `AFP2-H1-S2.publish*gate` | "해결 필요"가 있으면 발행 막기(화면을 우회해도 서버에서 거부) | `AFR-07` | P0 |
| `AFP2-H2-S1.ai*check` | 실명·내부 자료로 보이는 표현을 AI가 "확인 필요"로 표시 | `AFR-08` | P1 |
| `AFP3-H1-S1.sum*make` | 저장 때 3줄 요약을 1회 생성, 관리자가 [적용]해야 공개 | `AFR-09` | P1 |
| `AFP3-H1-S2.sum*box` | 글 위쪽 "AI 요약" 상자(접기·펼치기) | `AFR-10` | P1 |
| `AFP3-H2-S1.related` | 저장 때 비슷한 글을 계산해 "이어서 읽을 글" 카드로(공개 글 3개 미만이면 숨김) | `AFR-11` | P2 |
| `AFP4-H1-S1.ai*mark` | 모든 AI 결과에 표시, [적용] 전에는 반영되지 않음 | `AFR-12` | P0 |
| `AFP4-H1-S2.use*log` | 제안·적용·무시 횟수 기록(본문은 저장하지 않음) | `AFR-13` | P0 |
| `AFP4-H2-S1.once*limit` | 방문자 열람 때 AI 호출 없음, 관리자 호출은 월 한도와 80% 알림 | `AFR-14` | P0 |
| `AFP4-H2-S2.privacy` | 처리방침에 외부 AI 서비스 사용 추가 | `AFR-15` | P0 |

## 4. 지키는 원칙과 범위

- **AI는 제안만 합니다.** 저장하거나 공개되는 것은 내가 [적용]한 것뿐이고, 공개되는 AI 결과에는 표시("AI 초안", "AI 요약", "AI 추천")가 붙습니다.
- **방문자가 열 때는 AI를 부르지 않습니다.** 글을 저장할 때 1회만 만들어 두므로 방문자가 늘어도 비용이 늘지 않습니다.
- **AI로 보내지 않는 것:** 방문자의 이름·이메일·댓글, 관리자 계정 정보, API 키. 키는 서버 보안 설정에만 두고, 호출은 서버 함수가 관리자 로그인을 확인한 뒤에만 합니다.
- **AI가 실패하거나 한도를 넘어도** 글쓰기·발행·규칙 점검은 정상 동작합니다.
- **이번에 제외(Won't):** 댓글 자동 분류·답글 초안, 방문자 질문 답변(챗봇), 영어 번역, AI의 자동 발행·수정, 방문자별 맞춤 추천.
- **디자인:** 기존 시안 2를 유지하고, AI가 만든 것은 짙은 청록 "AI 초안" 표시로 구분합니다. 글쓰기 화면 오른쪽에 "AI 도우미" 패널(글쓰기 보조, 발행 전 점검, 첨부 요약)을 둡니다.

## 5. 출시 단계와 일정

| 단계 | 일정 | 범위 | 비고 |
|---|---|---|---|
| Phase A 안전과 틀 | 11-26 ~ 11-30 | `AFR-12`~`15`, `AFR-06`, `AFR-07` | AI 없이도 효과가 나는 점검과 전제 조건을 먼저 |
| Phase B 글쓰기 보조·요약 | 12-01 ~ 12-06 | `AFR-01` `02` `08` `09` `10` | **AI 제공자와 비용을 정한 뒤** 시작 |
| Phase C 확장 | 12-07 ~ 12-13 | `AFR-03` `04` `05` `11` | A·B의 이용 기록을 보고 진행 여부 결정 |

기획·승인은 11-24 ~ 11-25, QA는 각 단계 직후와 12-14 ~ 12-15, 최종 출시는 12-15, 안정화는 12-16 ~ 12-29입니다. 일정은 제안이며 아직 승인·착수 전입니다. 보안 규칙을 바꾸는 Phase A는 규칙 배포 → 로그인 없이·방문자 계정으로 거부 시험 → 화면 배포 순서로 진행합니다.

## 6. 성과 목표와 리스크

**목표(OKR):** 글을 쓰고 공개하는 반복 작업과 공개 전 실수 위험을 AI의 제안으로 줄인다.

| 지표 | 현재 | 목표 |
|---|---|---|
| 한 줄 요약이 채워진 공개 글 비율 | 50% | 100% |
| 공개 화면에 남은 자리표시자·전화번호 | 1건 이상(푸터 `[이름]`) | 0건 |
| AI 제안 적용률 | 측정 안 됨 | 측정 4주 뒤 기준값 확정 |
| 방문자 열람 한 번당 AI 호출 수 / 월 AI 호출 비용 | - | 0회 / 월 한도 이내 |

| 주요 리스크 | 영향 | 해결 전략 |
|---|---|---|
| AI가 틀린 요약·점검을 낸다 | 높음 | 표시 + [적용] 전에는 반영하지 않음, 방문자 요약은 관리자 확인 후 공개 |
| 회고·첨부 PDF 원문이 외부 AI로 나가 정보가 샌다 | 높음 | 회고는 "원문 보내지 않기" 선택지, 보내는 내용을 처리방침에 명시 |
| 호출 비용이 늘어난다 | 중간 | 저장 때 1회만, 월 한도와 80% 알림 |
| 점검이 놓치거나 지나치게 막는다 | 중간 | 규칙 점검이 기본, AI는 보완만, "확인했어요"로 사람이 최종 판단 |

## 7. 결정이 필요한 것

1. **AI 제공자와 모델** (품질, 비용, 한국어, 개인정보 약관) — 정하기 전에는 Phase B를 시작할 수 없습니다.
2. **월 호출 한도와 비용 한도(금액)** — 글 8편 기준 월 40~50회는 추정입니다.
3. 3줄 요약은 **관리자가 확인·[적용]해야만 공개**하는 것으로 확정할지.
4. 정확한 수치를 "확인 필요"로 둘지 "해결 필요"로 막을지.
5. 요약이 없는 기존 공개 글 2개를 일괄 정리할지, 푸터 `[이름]`을 먼저 고칠지.
