## 2026-11-17 (화면 반영)

- **시안 2 기반 화면 5개(첫 화면, 글 목록, 글 상세, 글쓰기, 관리자 로그인)를 실제 블로그에 반영함.** 글 목록에는 정렬과 제목 검색을 넣었어요.
- **글쓰기와 로그인 화면은 모양과 화면 동작까지만 만듦.** 공개글/나만 보기 선택, 작성/미리보기 탭은 동작하지만 저장과 로그인은 아직 연결하지 않았어요. 파이어베이스(Authentication, Firestore)를 연결할 때 붙여요.
- **나만 보기 글은 파이어베이스를 연결할 때 데이터베이스 규칙으로 막기로 함.** 화면에서 숨기는 것만으로는 부족해요(CLAUDE.md 주의사항).
- **글 상세의 관리자용 수정·삭제 막대는 로그인 연결 후에 넣기로 함.** 지금은 로그인 상태를 알 수 없어서 뺐어요.

## 2026-11-17 (회고 비공개 규칙)

- **회고는 나만 볼 수 있고 나만 쓸 수 있게 정함.** 로그인 전에는 회고 메뉴와 글이 보이지 않고, 글쓰기에서 회고는 나만 보기로 고정이라 공개 선택 버튼이 없어요. 로그인에 성공하면 그때 회고 메뉴와 글이 보여요.
- **지금의 정적 블로그에서는 회고 글을 아예 만들어 올리지 않는 방식으로 지킴.** 회고 글은 `private/` 폴더(깃헙에 올리지 않음)에 쓰고, 올리는 용도의 빌드에는 넣지 않아요. 내 컴퓨터에서만 `node build.js --with-private`로 미리 봐요.
- **로그인 후에 회고 메뉴와 글이 나타나는 동작은 파이어베이스를 연결할 때 만듦.** 정적 파일만으로는 로그인 여부를 확인할 수 없어서예요. 그때는 회고 글을 파이어베이스 데이터베이스에 넣고, 데이터베이스 규칙으로 관리자만 읽고 쓰게 막아요.
- **샘플 회고 글을 `posts/`에서 `private/`로 옮김.** `posts/`에 회고 글을 두면 빌드가 오류를 내서 실수로 공개하는 것을 막아요.

## 2026-11-17 (유저스토리, 지침, 관리자 화면 구성)

- **사용하는 사람을 방문자와 관리자 두 부류로 나누고 유저스토리 13개(방문자 6, 관리자 7)를 정함.** 내용은 `CLAUDE.md`의 "유저스토리"에 있어요. 새 기능은 이 스토리의 완료 기준을 만족해야 해요.
- **필수 지침을 `CLAUDE.md`에 추가함.** 글 쓰기·고치기·지우기는 관리자 계정만 가능하게 데이터베이스 규칙에서 막고, 관리자 계정은 한 명만 두며, 비공개 글은 존재 자체가 드러나지 않게 해요. 공개 전에 포트폴리오의 내부 자료·실명·수치와 샘플 글을 직접 확인해요.
- **품질 기준을 정함.** 사용자 입력은 걸러서 보여 주고, 모든 화면은 휴대폰에서도 가로 스크롤이 없게 하며, 키보드 사용과 글자 색 대비를 지키고, 삭제는 한 번 더 확인해요.
- **메뉴(카테고리)는 관리자가 이름, 개수, 순서를 직접 정하고, 같은 이름을 모든 화면에서 똑같이 쓰기로 함.** 기본 이름은 영어(PORTFOLIO, RETROSPECTIVE, STUDY)예요. 글이 남아 있는 메뉴는 지울 수 없어요.
- **관리자 페이지를 메뉴 관리와 글 관리 두 페이지로 나누기로 함.** 한 페이지에 모두 담으면 산만해서예요. 사이드바에서는 ADMIN 아래에 MANAGE MENUS, MANAGE POSTS 순서로 두고, NEW POST는 ADMIN 위 구분선 바로 아래에 둬요.
- **관리자 페이지의 첫 화면 통계(전체 글, 공개글 등 숫자 칸)는 넣지 않기로 함.**
- **위 관리자 화면 구성은 지금 체험판(아티팩트)에서 먼저 만들었고, 실제 블로그(`ai-pm-blog`)에는 아직 반영하지 않음.** 저장과 로그인이 파이어베이스 연결 뒤에야 동작하기 때문에 연결할 때 함께 옮겨요.

## 2026-11-17 (방문자 로그인과 댓글)

- **방문자는 Google 계정으로 로그인할 수 있게 정함.** 공개 글을 읽는 데는 로그인이 필요 없고, 댓글을 쓸 때만 로그인해요. 로그인은 Google만 쓰고 이메일·비밀번호 회원가입은 열지 않아요.
- **로그인한 방문자는 공개 글에만 댓글을 쓸 수 있게 정함.** 나만 보기 글과 회고에는 댓글이 없어요.
- **댓글 기능은 수정, 삭제, 작성 날짜·시간 표시, 대댓글, @ 호출을 모두 넣기로 정함.**
- **권한을 나눔.** 댓글 쓰기는 로그인한 사람, 수정은 쓴 사람만, 삭제는 쓴 사람과 관리자만 할 수 있어요. 관리자는 다른 사람의 댓글을 고칠 수 없어요.
- **관리자 권한과 방문자 권한을 분리함.** 이전에 정한 "회원가입 기능은 열지 않는다"는 이메일·비밀번호 가입을 뜻하는 것으로 정리했어요. Google 로그인한 방문자는 댓글 권한만 가지고 글쓰기와 관리는 할 수 없어요.
- **대댓글은 한 단계로 묶기로 함.** 답글에 답글을 달아도 원래 댓글 아래에 같은 묶음으로 보이고, 답글을 단 대상은 @이름으로 표시해요.
- **답글이 달린 댓글을 지우면 "삭제된 댓글입니다"로 남기고 답글은 유지하기로 함.** 답글이 없으면 그대로 지워요.
- **@로 부르면 사이드바 "@ 알림"에 나를 부른 댓글 수가 보이게 함.** 이메일 알림은 보내지 않아요.
- **방문자의 이메일은 다른 사람에게 보이지 않게 하고, 댓글에는 이름만 보이게 하는 것으로 정함(제안, 확정 필요).**
- **댓글 기능은 체험판(아티팩트)에서 먼저 만들었고, 실제 블로그에는 아직 반영하지 않음.** 체험판은 샘플 계정 3개로 로그인하는 모형이에요. 실제 블로그에서는 파이어베이스 Authentication의 Google 로그인과 데이터베이스(Firestore) 보안 규칙으로 만들어요.
- **아직 정하지 않은 것.** 댓글이 달렸을 때 이메일 알림을 보낼지, 부적절한 댓글을 삭제 말고 숨기는 기능을 둘지, 댓글 글자 수 제한(체험판은 500자)을 그대로 쓸지는 정하지 않았어요.

## 2026-11-17 (자동 커밋)

- **수정사항이 있으면 자동으로 커밋하기로 정함.** Claude가 응답을 마칠 때마다(Stop) 바뀐 파일이 있으면 한국어 메시지("자동 저장: 파일명 수정")로 커밋해요. 스크립트는 `.claude/hooks/auto-commit.sh`, 설정은 `.claude/settings.local.json`에 있어요.
- **자동으로 올리지는(push) 않기로 함.** 저장소가 공개라서 올리기 전에 직접 확인하려는 것이에요. 올리는 것은 요청할 때만 해요.
- **비밀 값 보호.** `.env`, `.pem`, `credentials` 같은 이름의 파일이 바뀌어 있으면 자동 커밋을 멈추고 알려요.
- **`.claude/` 폴더는 깃에 올리지 않기로 함.** 내 컴퓨터의 개인 설정이라서예요.
- **적용 범위.** Claude를 `ai-pm-blog` 폴더에서 열었을 때 동작해요. 한 응답이 끝날 때 한 번에 묶어 커밋하므로 커밋 하나에 여러 파일이 들어갈 수 있어요.

## 2026-11-17 (조회수, 공유하기, 썸네일)

- **회고를 제외한 글은 방문자가 열 때마다 조회수가 쌓이게 정함.** 회고 같은 나만 보기 메뉴의 글은 조회수를 세지 않고 보여 주지도 않아요. 관리자가 글을 열어 본 것도 세지 않아요(본인 확인으로 숫자가 부풀지 않게).
- **조회수는 글 목록, 첫 화면 목록, 글 상세에 보이고, 글 관리 목록에는 조회수 열을 둠.**
- **공유하기는 공개 글에만 두기로 정함.** 링크 복사와 X·Facebook·LinkedIn 공유를 넣었고, 나만 보기 글과 회고에는 버튼이 없어요.
- **모든 글에 썸네일을 두기로 정함.** 기본 모양 6개 중에서 고르거나 이미지를 올려요. PNG·JPG·WebP·GIF, 1MB 이하만 받고 SVG는 받지 않아요.
- **각 메뉴의 샘플 글을 3개씩으로 늘림.** (요청은 최소 2개였어요.) 모두 `[샘플]` 표시가 있고, 공개 전에 지워요.
- **체험판의 조회수와 이미지 올리기는 이 브라우저 안에서만 동작함.** 실제 블로그에서는 조회수를 파이어베이스 데이터베이스에, 썸네일 이미지를 파일 저장소(Storage)에 저장해야 해요. 앞서 "이미지 올리기"를 후순위(P2) 후보로 두었는데, 썸네일 올리기가 생기면서 파일 저장소 연결이 Phase 1~2에 필요해졌어요.
- **아직 정하지 않은 것.** 같은 사람이 새로고침으로 조회수를 반복해서 올리는 것을 막는 방법, 인기순 정렬을 둘지, 이미지를 올리지 않았을 때 기본 썸네일을 자동으로 만들지 여부는 정하지 않았어요.
