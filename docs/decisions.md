## 2026-11-17 (방문자 로그인과 댓글)

- **방문자는 Google 계정으로 로그인할 수 있게 정함.** 공개 글을 읽는 데는 로그인이 필요 없고, 댓글을 쓸 때만 로그인해요. 로그인은 Google만 쓰고 이메일·비밀번호 회원가입은 열지 않아요.
- **로그인한 방문자는 공개 글에만 댓글을 쓸 수 있게 정함.** 나만 보기 글과 회고에는 댓글이 없어요.
- **댓글 기능은 수정, 삭제, 작성 날짜·시간 표시, 대댓글, @ 호출을 모두 넣기로 정함.**
- **권한을 나눔.** 댓글 쓰기는 로그인한 사람, 수정은 쓴 사람만, 삭제는 쓴 사람과 관리자만 할 수 있어요. 관리자는 다른 사람의 댓글을 고칠 수 없어요.
- **관리자 권한과 방문자 권한을 분리함.** 이전에 정한 "회원가입 기능은 열지 않는다"는 이메일·비밀번호 가입을 뜻하는 것으로 정리했어요. Google 로그인한 방문자는 댓글 권한만 가지고 글쓰기와 관리는 할 수 없어요.
- **대댓글은 한 단계로 묶기로 함.** 답글에 답글을 달아도 원래 댓글 아래에 같은 묶음으로 보이고, 답글을 단 대상은 @이름으로 표시해요.
- **답글이 달린 댓글을 지우면 "삭제된 댓글입니다"로 남기고 답글은 유지하기로 함.** 답글이 없으면 그대로 지워요.
- **@로 부르면 사이드바 "@ 알림"에 나를 부른 댓글 수가 보이게 함.** 이메일 알림은 보내지 않아요.
- **방문자의 이메일은 다른 사람에게 보이지 않게 하고, 댓글에는 이름만 보이게 하는 것으로 정함(제안, 확정 필요).**
- **댓글 기능은 체험판(아티팩트)에서 먼저 만들었고, 실제 블로그에는 아직 반영하지 않음.** 체험판은 샘플 계정 3개로 로그인하는 모형이에요. 실제 블로그에서는 파이어베이스 Authentication의 Google 로그인과 데이터베이스(Firestore) 보안 규칙으로 만들어요.
- **아직 정하지 않은 것.** 댓글이 달렸을 때 이메일 알림을 보낼지, 부적절한 댓글을 삭제 말고 숨기는 기능을 둘지, 댓글 글자 수 제한(체험판은 500자)을 그대로 쓸지는 정하지 않았어요.

- **각 메뉴의 샘플 글을 3개씩으로 늘림.** (요청은 최소 2개였어요.) 모두 `[샘플]` 표시가 있고, 공개 전에 지워요.

- **아직 정하지 않은 것.** 같은 사람이 새로고침으로 조회수를 반복해서 올리는 것을 막는 방법, 인기순 정렬을 둘지, 이미지를 올리지 않았을 때 기본 썸네일을 자동으로 만들지 여부는 정하지 않았어요.

## 2026-11-17 (SEO 점검과 수정)

- **SEO 점검 결과를 바탕으로 문제를 모두 고침.** 점검에서 메타 설명, 대표 주소, 공유 카드, 구조화 데이터, 사이트맵, robots.txt, 파비콘, 404 페이지가 없고, 본문 제목 단계가 h1 다음에 h3로 건너뛰며, 관리자 화면이 검색에 잡히고, 공개 글쓰기 화면에 회고 메뉴 이름이 보이는 문제를 찾았어요.
- **사이트 주소(`siteUrl`)는 아직 정하지 않음.** 배포할 곳이 정해져야 해서 비워 뒀어요. 비어 있으면 대표 주소, 사이트맵, RSS, 공유 이미지 주소는 만들지 않고, 빌드할 때 알림으로 알려 줘요. `--site-url=`로 빌드하면 모두 만들어져요.
- **관리자 화면과 404는 noindex로 정함.** robots.txt로 막지 않고 noindex를 써요. (막아 버리면 검색 로봇이 noindex 표시를 읽지 못해서예요.)
- **공개 빌드의 글쓰기 화면에서 비공개 메뉴를 뺌.** 회고 메뉴의 존재가 로그인 전에 드러나지 않게 했어요.
- **공유 이미지와 아이콘을 만들어 둠.** `assets/og-default.png`(1200x630), `favicon.svg`, `icon-192.png`, `apple-touch-icon.png`예요. 글마다 다른 공유 이미지는 글 머리말의 `image`로 정해요. 썸네일 기본 모양은 SVG라 공유 카드에 쓸 수 없어요.
- **글꼴은 화면 표시를 막지 않게 늦게 불러오도록 바꿈.** 글꼴 파일을 직접 두는 방식(서브셋)은 후순위로 남겼어요.
- **아직 정하지 않은 것.** 사이트 주소와 호스팅, 주소에서 `.html`을 뗄지(`cleanUrls`), 구글 서치콘솔·네이버 서치어드바이저 등록 시점이에요.

## 2026-11-17 (관리자 로그인과 글 저장)

- **관리자 로그인은 파이어베이스 이메일·비밀번호로 하고, 관리자는 `admin` 표시(custom claim)가 붙은 계정 한 명으로 정함.** 회원가입 화면은 만들지 않았고, 계정은 콘솔에서 직접 만들어요.
- **글은 파이어베이스 데이터베이스(Firestore, 서울 `asia-northeast3`)의 `posts`에 저장하기로 함.** 본문은 마크다운으로 저장해요. 체험판의 서식 도구(글꼴·크기 등)는 아직 연결하지 않았어요. 서식 있는 글(HTML) 저장은 별도로 정해요.
- **보안 규칙을 올림(`firestore.rules`).** 공개 글만 누구나 읽고, 쓰기·수정·삭제는 관리자만 하며, 회고는 항상 나만 보기여야만 저장돼요. 비로그인 상태로 시험해서 전체 글 조회, 비공개 설정 읽기, 글 쓰기가 모두 막히는 것을 확인했어요.
- **방문자에게 보이는 글은 빌드할 때 파이어베이스에서 가져와 HTML로 만들기로 함.** 검색(SEO)에 유리하기 때문이에요. 대신 글을 쓰거나 고친 뒤에는 다시 빌드하고 배포해야 사이트에 반영돼요. 자동 반영(서버 함수 등)은 유료 요금제가 필요해서 나중에 정해요.
- **회고 이름은 공개 파일에 넣지 않고 `settings/private` 문서(관리자만 읽기)에 둠.** 글쓰기 화면의 회고 메뉴는 관리자가 로그인한 뒤 불러와요.
- **글 주소(slug)를 글쓰기에서 직접 정할 수 있게 함.** 비우면 글 번호를 써요. 영어 소문자·숫자·하이픈만 허용해요.
- **글 안의 링크와 이미지 주소는 http(s), mailto, 상대 주소만 허용함.** `javascript:` 같은 주소는 막아요.
- **체험판의 로그인·글쓰기·조회수·댓글·공유·썸네일·서식 도구는 아직 실제 블로그에 연결하지 않음.** 이번에 연결한 것은 관리자 로그인, 글쓰기·수정, 글 관리(공개 전환·삭제), 빌드의 글 가져오기예요.
- **요금제는 무료(Spark) 그대로.** 썸네일 이미지 올리기(Storage)를 연결할 때 유료 전환이 필요해요.

## 2026-11-17 (첫 배포)

- **파이어베이스 호스팅으로 첫 배포를 함.** 주소는 `https://my-blog-test-b439a.web.app`이에요. 시험 단계라서 기본 주소를 그대로 쓰고, 이 주소로 대표 주소(canonical), 사이트맵, RSS를 만들었어요.
- **관리자 화면(`admin/`)도 같은 사이트에 올라감.** 검색에서는 빠지도록(noindex) 했고, 로그인한 관리자 외에는 데이터를 읽거나 쓰지 못해요(보안 규칙).
- **쪽(HTML)은 캐시를 쓰지 않도록 `firebase.json`에 설정함.** 글을 다시 배포하면 바로 보여요.
- **배포 시험 결과.** 모든 쪽이 200으로 열리고, 없는 주소는 404 페이지로 가며, 비로그인 상태로 공개 글만 조회되고 회고 관련 글자는 0개예요. 구글 로그인은 배포 주소에서 허용돼요.
- **배포 전에 해결하지 못한 것(시험 단계라 그대로 올림).** `[샘플]` 글 2개, 시험 글 `ㅁㄴㅇㄹ`, 작성자·연락처 자리표시자(`[이름]`, `[이메일 주소]`)가 사이트에 그대로 보여요. 본격적으로 공개하기 전에 지워야 해요.
- **아직 정하지 않은 것.** 사용할 도메인(기본 주소를 계속 쓸지), 구글 서치콘솔·네이버 서치어드바이저 등록, 시험 글 삭제 시점이에요.

## 2026-11-17 (시안 디자인과 관리자 기능을 실제 블로그에 연결)

- **공개 화면과 관리자 화면 모두 체험판(시안 2)의 디자인과 사이드바를 그대로 따르기로 함.** 첫 화면 타일 배경에 글 썸네일, 목록 행에 썸네일과 오른쪽 정렬 날짜·조회수, 글 상세에 커버 이미지와 작은 공유하기 버튼이 있어요. 관리자 사이드바는 ALL POSTS, 메뉴들, 구분선, NEW POST, ADMIN 아래 MANAGE MENUS·MANAGE POSTS 순서예요.
- **관리자 화면을 6개로 나눔(로그인, 글 관리, 메뉴 관리, 글쓰기, 글 목록, 글 보기).** 내용은 로그인 확인 뒤에 불러와서 그리고, 나만 보기 글(회고)은 이 화면에서만 볼 수 있어요. 관리자가 로그인한 채 공개 화면을 보면 사이드바가 관리자 메뉴로 바뀌어요. 이 코드는 관리자 로그인 표시가 있는 브라우저에서만 불러와서 일반 방문자 화면은 가볍게 유지해요.
- **메뉴(카테고리)를 관리자가 직접 고치게 함.** 공개 메뉴는 `settings/menus`(누구나 읽기, 빌드가 사용), 나만 보기 메뉴와 전체 순서는 `settings/private`(관리자만)에 저장해요. 빌드는 `settings/menus`를 가져오고, 없으면 `site.config.json`의 메뉴를 써요. 메뉴 이름은 하나만 써서 모든 화면에 똑같이 보여요. 글이 있는 메뉴는 지울 수 없고, 메뉴를 나만 보기로 바꾸면 그 메뉴의 공개 글도 모두 나만 보기로 바뀌어요.
- **글 본문을 서식 있는 HTML로 저장하기로 함(`format: "html"`).** 글쓰기 도구창(글꼴, 크기, 굵기, 색, 정렬, 목록, 인용, 링크)을 쓰고, 저장할 때와 빌드할 때 같은 걸러내기 코드(`assets/sanitize.js`)로 허용한 태그·스타일만 남겨요. 이전에 마크다운으로 저장한 글(`format` 없음)도 그대로 읽혀요.
- **썸네일은 기본 모양 6개 또는 올린 이미지.** 올린 이미지는 파일 저장소(Storage)의 `thumbs/`에 두고 글에는 주소만 저장해요. 규칙은 PNG·JPG·WebP·GIF, 1MB 이하, 올리기·지우기는 관리자만이에요. SVG는 받지 않아요.
- **요금제는 Blaze.** 이미지 저장소를 쓰기 위해 정했어요. 저장소 위치는 무료 위치(US-EAST1)로 골랐어요(나중에 바꿀 수 없어요).
- **조회수는 `views/{글 번호}` 문서에 저장하고, 공개 글에서만 1씩 올릴 수 있게 규칙으로 제한함.** 관리자가 연 것과, 같은 브라우저에서 이미 센 글은 세지 않아요. 나만 보기 메뉴의 글에는 조회수가 없어요. 새로고침이나 다른 브라우저로 반복해서 올리는 것은 완전히 막지 못해요(열린 결정).
- **공유하기는 공개 글에만 있음.** 링크 복사, X, Facebook, LinkedIn이에요. 주소는 글의 대표 주소(canonical)를 써요.
- **스크립트·스타일·설정 파일도 캐시를 쓰지 않도록 설정함.** 배포 직후 브라우저가 어제 받아 둔 옛 관리자 스크립트를 1시간 동안 쓰는 바람에 로그인 뒤 화면이 멈춘 일이 있었어요. 자세한 내용은 `docs/failures/`에 적어요.
- **아직 만들지 않은 것.** 방문자 구글 로그인과 댓글(수정, 삭제, 대댓글, @ 호출, @ 알림)이에요. 댓글 보안 규칙을 먼저 설계해야 해요.

## 2026-11-17 (방문자 로그인과 댓글)

- **방문자는 관리자와 같은 구글 로그인으로 로그인함.** 사이드바 아래 "Google 로그인"으로 로그인하고, 같은 브라우저에서는 관리자와 로그인 상태를 같이 써요. 방문자 코드는 로그인 표시가 있거나 댓글·조회수가 필요한 화면에서만 파이어베이스를 불러와요.
- **댓글은 `comments` 컬렉션에 저장함.** 글 번호, 부모 댓글, 작성자 번호(uid), 이름, 관리자 표시, 내용(500자 이하), @ 호출 목록, 작성 시각을 저장해요. 이메일은 저장하지 않아요.
- **댓글 규칙.** 누구나 읽고, 구글로 로그인한 사람만 쓰고(공개 글에만, 나만 보기 글에는 불가), 쓴 사람만 내용을 고치고, 쓴 사람과 관리자만 지워요. "관리자" 이름과 관리자 표시는 관리자만 써요. 로그인 없이 쓰기·삭제가 막히는 것을 확인했어요.
- **답글이 달린 댓글을 지우면 내용을 비우고 "삭제된 댓글입니다"만 남김.** 답글이 모두 사라지면 그 자리도 지워요. 대댓글은 한 단계만 있어요.
- **@ 알림은 댓글에 저장한 호출 목록으로 찾음.** 알림 화면(`mentions.html`)은 검색에서 빠지게 했고, 읽은 알림은 이 브라우저에만 기록해요.
- **글을 지우거나 나만 보기로 바꾸면 그 글의 댓글도 함께 지움.** 나만 보기 글의 댓글이 주소만 알면 읽히는 일을 막기 위해서예요(메뉴를 나만 보기로 바꿀 때도 같아요).
- **한계.** 구글 계정이 있으면 누구나 댓글을 쓸 수 있어서 스팸은 관리자가 지워야 해요. 실제 로그인 상태에서의 허용 동작은 가짜 파이어베이스로만 시험했고, 직접 써 보며 확인해야 해요.
