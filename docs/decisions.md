## 2026-11-17 (방문자 로그인과 댓글)

- **방문자는 Google 계정으로 로그인할 수 있게 정함.** 공개 글을 읽는 데는 로그인이 필요 없고, 댓글을 쓸 때만 로그인해요. 로그인은 Google만 쓰고 이메일·비밀번호 회원가입은 열지 않아요.
- **로그인한 방문자는 공개 글에만 댓글을 쓸 수 있게 정함.** 나만 보기 글과 회고에는 댓글이 없어요.
- **댓글 기능은 수정, 삭제, 작성 날짜·시간 표시, 대댓글, @ 호출을 모두 넣기로 정함.**
- **권한을 나눔.** 댓글 쓰기는 로그인한 사람, 수정은 쓴 사람만, 삭제는 쓴 사람과 관리자만 할 수 있어요. 관리자는 다른 사람의 댓글을 고칠 수 없어요.
- **관리자 권한과 방문자 권한을 분리함.** 이전에 정한 "회원가입 기능은 열지 않는다"는 이메일·비밀번호 가입을 뜻하는 것으로 정리했어요. Google 로그인한 방문자는 댓글 권한만 가지고 글쓰기와 관리는 할 수 없어요.
- **대댓글은 한 단계로 묶기로 함.** 답글에 답글을 달아도 원래 댓글 아래에 같은 묶음으로 보이고, 답글을 단 대상은 @이름으로 표시해요.
- **답글이 달린 댓글을 지우면 "삭제된 댓글입니다"로 남기고 답글은 유지하기로 함.** 답글이 없으면 그대로 지워요.
- **@로 부르면 사이드바 "@ 알림"에 나를 부른 댓글 수가 보이게 함.** 이메일 알림은 보내지 않아요.
- **방문자의 이메일은 다른 사람에게 보이지 않게 하고, 댓글에는 이름만 보이게 하는 것으로 정함(제안, 확정 필요).**
- **댓글 기능은 체험판(아티팩트)에서 먼저 만들었고, 실제 블로그에는 아직 반영하지 않음.** 체험판은 샘플 계정 3개로 로그인하는 모형이에요. 실제 블로그에서는 파이어베이스 Authentication의 Google 로그인과 데이터베이스(Firestore) 보안 규칙으로 만들어요.
- **아직 정하지 않은 것.** 댓글이 달렸을 때 이메일 알림을 보낼지, 부적절한 댓글을 삭제 말고 숨기는 기능을 둘지, 댓글 글자 수 제한(체험판은 500자)을 그대로 쓸지는 정하지 않았어요.

## 2026-11-17 (SEO 점검과 수정)

- **SEO 점검 결과를 바탕으로 문제를 모두 고침.** 점검에서 메타 설명, 대표 주소, 공유 카드, 구조화 데이터, 사이트맵, robots.txt, 파비콘, 404 페이지가 없고, 본문 제목 단계가 h1 다음에 h3로 건너뛰며, 관리자 화면이 검색에 잡히고, 공개 글쓰기 화면에 회고 메뉴 이름이 보이는 문제를 찾았어요.
- **사이트 주소(`siteUrl`)는 아직 정하지 않음.** 배포할 곳이 정해져야 해서 비워 뒀어요. 비어 있으면 대표 주소, 사이트맵, RSS, 공유 이미지 주소는 만들지 않고, 빌드할 때 알림으로 알려 줘요. `--site-url=`로 빌드하면 모두 만들어져요.
- **관리자 화면과 404는 noindex로 정함.** robots.txt로 막지 않고 noindex를 써요. (막아 버리면 검색 로봇이 noindex 표시를 읽지 못해서예요.)
- **공개 빌드의 글쓰기 화면에서 비공개 메뉴를 뺌.** 회고 메뉴의 존재가 로그인 전에 드러나지 않게 했어요.
- **공유 이미지와 아이콘을 만들어 둠.** `assets/og-default.png`(1200x630), `favicon.svg`, `icon-192.png`, `apple-touch-icon.png`예요. 글마다 다른 공유 이미지는 글 머리말의 `image`로 정해요. 썸네일 기본 모양은 SVG라 공유 카드에 쓸 수 없어요.
- **글꼴은 화면 표시를 막지 않게 늦게 불러오도록 바꿈.** 글꼴 파일을 직접 두는 방식(서브셋)은 후순위로 남겼어요.
- **아직 정하지 않은 것.** 사이트 주소와 호스팅, 주소에서 `.html`을 뗄지(`cleanUrls`), 구글 서치콘솔·네이버 서치어드바이저 등록 시점이에요.

## 2026-11-17 (글·메뉴·삭제가 바로 반영되도록 서버에서 그리기)

- **페이지를 서버(Cloud Functions 2세대 `site`, 서울 `asia-northeast3`)가 방문할 때마다 그리기로 함.** 글을 쓰고 고치고 지우거나 메뉴를 바꾸면 배포 없이 바로 반영되고, 검색 엔진도 완성된 HTML을 읽어서 검색 노출(SEO)에 불리하지 않아요. 선택지였던 "브라우저에서 덧입히기"는 검색이 보는 원본이 낡은 채로 남아서 고르지 않았어요. 사이트맵과 RSS도 매번 새로 만들어져요.
- **같은 코드를 둘이 씀.** 루트의 `build.js`가 모든 페이지를 만드는 `generate(provider)`를 내보내고, 명령줄 빌드는 파이어베이스 REST로, 서버는 관리자 SDK로 공개 글만 가져와요. 서버 꾸러미는 `node build.js --ssr`이 `functions/site/`로 복사해요(이 폴더는 깃헙에 올리지 않아요).

- **글·메뉴 변경 안내 문구를 고침.** 관리자 화면의 "다시 배포해야 반영돼요" 안내를 없앴어요. 디자인·스크립트·서버 함수 코드를 바꿨을 때만 배포해요.

## 2026-11-17 (이미지 한도 10MB와 본문 이미지)

- **이미지 한 장의 한도를 1MB에서 10MB로 올림(썸네일과 본문 이미지 모두).** 화면 검사(`MAX_IMG`)와 저장소 규칙(`storage.rules`)을 같이 바꿨어요. 실제로 막는 곳은 저장소 규칙이에요. 형식은 PNG·JPG·WebP·GIF만이고 SVG는 계속 받지 않아요. 로그인 없이 올리기, 파일 목록 보기, 다른 폴더 읽기가 막히는 것을 확인했어요.
- **글 본문에 이미지를 넣을 수 있게 함.** 글쓰기 도구창의 "이미지"에서 설명(alt)을 쓰고 이미지를 고르면 `images/`에 올라가고 커서 자리에 들어가요. 이미지 설명은 눈이 불편한 분과 검색을 위한 것이라 쓰도록 안내해요(비워도 저장은 돼요).
- **본문에는 우리 파일 저장소의 이미지 주소만 허용함.** 글을 걸러내는 코드(`assets/sanitize.js`)가 저장할 때, 서버가 그릴 때, 미리보기 때 모두 같은 규칙으로 걸러요. 다른 사이트 주소, `data:`, `javascript:` 주소와 이벤트 속성(`onerror` 등)은 모두 버려요. 위험한 입력으로 시험해서 걸러지는 것을 확인했어요.
- **이미지만 있는 글도 저장할 수 있음**(본문 글자가 없어도 이미지가 있으면 통과).
- **한계.** 글이나 이미지를 지워도 저장소의 파일은 남아요(쓰지 않는 파일이 쌓일 수 있어요). 큰 이미지는 불러오는 데이터 사용량과 글 화면 속도에 영향을 줘요. 사진은 올리기 전에 크기를 줄이면 좋아요.

## 2026-11-17 (구글 애널리틱스 GA4 연결 준비)

- **방문 통계는 구글 애널리틱스(GA4)로 보기로 함.** 원하는 것은 (1) 홈 화면 방문자 숫자, (2) 페이지별 방문자 숫자, (3) 지역·기기·OS 같은 정보, (4) 가장 많이 읽힌 글이에요. 모두 GA4가 기본으로 모아 줘서 따로 만들지 않아요. 글 화면의 조회수(직접 센 숫자)는 그대로 두고, GA는 운영자가 보는 통계예요.
- **측정 ID(`G-`로 시작)를 `site.config.json`의 `analyticsId`에 넣으면 켜짐.** 비어 있으면 아무것도 넣지 않아요. 코드는 `assets/analytics.js`이고, 서버가 그리는 공개 페이지(홈, 목록, 글, 소개)에만 들어가요. 관리자 화면, @ 알림, 404 페이지에는 넣지 않아요.
- **관리자가 로그인해 둔 브라우저에서는 측정하지 않음.** 내 방문이 방문자 숫자에 섞이지 않게 하려는 거예요. 로그아웃한 브라우저나 다른 기기에서 내가 열면 측정돼요(GA의 "내부 트래픽" 필터로 막을 수 있어요).
- **개인정보 안내가 필요함.** GA는 쿠키와 접속 정보를 모아요. 공개하기 전에 방문 통계를 모은다는 안내(개인정보 처리방침)를 정하는 것이 열린 결정이에요. 광고용 신호(Google 신호)는 켜지 않는 것을 권장해요.
- **GA4 측정 ID `G-L0533VG5G0`를 연결하고 배포함(2026.11.17).** 홈, 목록, 글, 소개 페이지에 들어가고 관리자 화면·@ 알림·404에는 들어가지 않는 것을 실제 사이트에서 확인했어요. 측정 ID는 공개되는 값이라 코드와 저장소에 있어도 돼요.

## 2026-11-17 (GA 이벤트 택소노미 보고서: 현재 적용 상태 기록)

- **GA 이벤트 택소노미 보고서는 "앞으로 할 일"이 아니라 "지금 적용된 상태(TO-BE)"를 기록하는 문서로 정함**(`docs/Intent-Notes-GA-Event-Taxonomy.pdf`, 지금은 `docs/GA-Taxonomy.pdf`, 원본 `docs/ga-event-taxonomy.html`, 11쪽). 처음에는 새 이벤트 8개를 설계하는 계획서로 썼지만, 사용자가 현재 상태가 TO-BE라고 바로잡아서 다시 썼어요.
- **AS-IS는 직접 센 글별 "조회 N"뿐이던 상태, TO-BE는 GA4 연결 후의 현재 상태.** 홈 방문자, 페이지별 방문자, 지역·기기·OS, 많이 읽은 글 4가지를 GA가 자동으로 모으는 이벤트(`page_view`, `scroll`, `click`, `user_engagement` 등)와 측정기준만으로 답해요. 맞춤 이벤트는 만들지 않았어요(0개).
- **"가장 많이 읽은 글"은 조회수, 평균 참여 시간, `scroll`(90%) 건수를 겹쳐서 봄.**
- **홈 방문이 GA에 `/`와 `/index.html` 두 줄로 나뉘던 문제를 고침(2026.11.17).** 사이드바 로고 링크를 `/`(폴더 주소)로 바꾸고, `/index.html`로 들어오는 방문은 `/`로 영구 이동(301, `firebase.json`의 `redirects`)시켜요. 고치기 전에 쌓인 데이터는 두 줄을 합쳐서 봐야 해요(페이지 경로 정규식 필터 `^/(index\.html)?$`). 실제 사이트에서 이동과 링크를 확인했어요.
- **글 화면의 조회수(직접 센 숫자)는 표시용으로 그대로 두고, 분석은 GA 기준으로 함.**

## 2026-11-17 (글에 파일 첨부)

- **글에 파일을 첨부할 수 있게 함.** 글쓰기 화면의 "첨부 파일"에서 올리고, 공개 글 페이지 아래의 "첨부 파일" 목록(이름, 크기, 형식)에서 방문자가 내려받아요. 서버가 그리는 페이지에 들어가서 배포 없이 바로 반영돼요.
- **한도는 파일당 25MB, 글당 5개로 정함.** 25MB는 발표 자료나 보고서 PDF, 한글 문서에 충분하고, 내려받기 요금(무료 사용량 밖에서 1GB당 약 0.12달러)을 크게 늘리지 않는 크기예요. 더 큰 파일은 압축하거나 링크로 걸어요. 한도를 바꾸려면 `assets/admin-app.js`의 `MAX_FILE`과 `storage.rules`의 `26214400`을 함께 고쳐요.
- **허용 형식은 확장자 허용 목록.** PDF, doc·docx·xls·xlsx·ppt·pptx·hwp·hwpx, txt·csv·md·json, zip, png·jpg·gif·webp. 실행 파일, 스크립트, HTML, SVG는 받지 않아요(안에 코드가 들어갈 수 있어서예요). 저장소 규칙이 파일 이름의 확장자를 검사하고, 화면도 같은 목록으로 거부해요.
- **파일 이름은 "무작위번호.확장자"로 올리고, 원래 이름은 글에 따로 저장함.** 한글 이름도 깨지지 않고, 내려받을 때 원래 이름으로 저장돼요(올릴 때 `attachment; filename*=UTF-8''원래이름`을 붙여요).
- **글에서 뺀 파일은 저장소에서도 지움**(글을 저장할 때). 글을 지울 때도 첨부 파일을 지워요. 저장하지 않고 나간 경우, 썸네일·본문 이미지는 저장소에 남을 수 있어요.
- **나만 보기 글의 첨부 파일.** 목록은 공개되지 않지만, 내려받기 주소(비밀 토큰 포함)를 아는 사람은 받을 수 있어요. 비밀 자료는 올리지 않는 것이 좋아요.
- **GA.** 첨부 파일 링크는 외부 주소로 나가는 링크라 GA의 `click`(향상된 측정)에 잡힐 수 있어요. 파일 형식에 따라 `file_download`로 잡힐 수도 있고, 확인은 측정 후에 해요.

## 2026-11-17 (이전·다음 글은 같은 메뉴 안에서만)

- **관리자 글 보기(`admin/view.html`)에도 같은 메뉴 안의 이전·다음 글 링크를 넣음(2026.11.17).** 관리자 화면에는 이 링크가 없어서 보이지 않았어요. 관리자는 나만 보기 글(회고)도 보기 때문에, 같은 메뉴 안의 모든 글(공개·나만 보기 모두)을 날짜순으로 이어요. 나만 보기 글에는 "나만 보기" 표시가 같이 나와요. 방문자 화면과 마찬가지로 다른 메뉴로는 넘어가지 않아요. 이 변경은 화면 코드라서 사이트 파일 배포로 반영돼요.

## 2026-11-24 (발행 전 점검 항목 재구성)

- **점검은 5가지예요**: 자리표시자, 개인정보·고객정보, 회사 내부 자료, 오탈자·어색한 문장, 제목·요약과 본문의 일치. 전화번호(규칙)와 실명(AI)을 개인정보·고객정보 한 항목으로 합쳤고, AI는 실명 외에 회사·소속·학교·주소·고객사·계약 정보도 찾아요.
- **막는 정도**: 자리표시자·전화번호는 "해결 필요"(저장 막기, 보안 규칙도 막음). 개인정보·고객정보와 회사 내부 자료의 AI 발견은 "확인 필요"("확인했어요" 필요). 오탈자와 제목·요약 불일치는 "수정 권장"으로 알려 주기만 하고 발행을 막지 않아요(맞춤법 지적은 틀릴 수 있어서).
- **점검 범위**: 규칙과 AI 모두 본문과 함께 제목·한 줄 요약·검색용 설명을 봐요. AI에는 이 글자들도 함께 보내요(처리방침의 "글 본문" 범위 안).
- 오탈자는 한 번에 최대 5개까지만 보여 줘요(눈에 띄는 것 위주).

## 2026-11-24 (검색용 설명을 한 줄 요약에 합침)

- **관리자 로그인은 구글 계정 한 개로 두고, 평가자용 임시 접속 코드를 더했어요.** 이메일·비밀번호 로그인은 계속 꺼 두었고, 평가자는 먼저 익명 로그인을 하고, 코드를 서버 함수(`reviewer`)에 보내요. 코드가 맞으면 서버가 그 익명 계정에 `reviewer` 표시와 만료 시각을 붙여요(관리자 `admin` 표시는 붙지 않아요). 로그인 토큰을 서명하는 방식은 서버 권한(`iam.serviceAccounts.signBlob`)이 없어 쓰지 못했어요.

- **임시인 이유:** 토큰에 만료 시각(`until` = 코드 만료일과 12시간 중 이른 쪽)이 들어 있고 `firestore.rules`·`storage.rules`·AI 함수가 모두 확인해요. 코드는 해시만 저장하고(`reviewerAccess/current`), 새 코드로 바꾸면 새 입장이 막혀요. 이미 들어온 평가자는 `until`까지만 쓸 수 있어요.

## 2026-11-25 (첨부 요약 적용 단계)

- 초안 삭제는 AI 이용 현황에 "무시"로 세요. 적용은 저장할 때 한 번 세는 방식을 그대로 써요.

## 2026-11-25 (AI 도우미 안내 보강)

- 시험: 로컬 가짜 서버로 80% 안내, 한도 도달, 빈 본문(서버 호출 0회), 10초 안내, 호출 뒤 83→84% 증가, 모바일(375px) 한 줄·가로 스크롤 없음, 서버 429 응답을 확인했어요. 실제 서버의 한도 초과는 시험하지 못했어요.
